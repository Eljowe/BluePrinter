# Load a library snippet into the looper to overdub and save a new version

## Problem

A saved snippet is a dead end: it can be played, analysed, exported and
retimed, but it can never be used as the bed for new work. The looper only ever
starts from an empty fresh capture, so building on an earlier idea means
re-recording it by hand. Users want to drop a saved snippet into the looper,
overdub on top of it, and keep the result as a new snippet without destroying
the original.

## Current behaviour

- The loop lives in the shared `recordBuffer` and is described by `Looper`'s
  `start` / `length` / `fullLength`. Loop audio only ever comes from a fresh
  capture (`trimLooperToMusicalGrid` → `Looper::setGridTrimmed`) or an overdub
  layer; there is no path that seeds the loop from an existing buffer.
- `SnippetLibrary` stores each snippet as a `shared_ptr<const AudioBuffer<float>>`
  plus peaks, `sampleRate`, channels and samples. `SnippetCard.jsx` offers
  play/analyse/export/gain/favourite but not "load into looper".
- `PluginProcessor::saveLoopSnippet()` (`Source/PluginProcessor.cpp:2039`) always
  creates a **new** snippet from `recordBuffer[looper.start, +length)` with a
  timestamp default name; the source is never modified.
- `recordBuffer` is allocated for `maxRecordingSeconds = 120` seconds at the
  session rate (`Source/PluginProcessor.cpp:1078`). An overdub layer is written
  *after* `fullLength`, so a loop whose `fullLength` is near capacity leaves no
  room for the layer to grow.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Load a saved snippet into the looper (resampled to the session
rate), overdub on top of it, and save the result as a new snippet with the
source left untouched.

**Decisions settled during triage:**

1. **Trigger:** a **Load into looper** button in the snippet card's expanded
   action row (`.snippet-actions`, beside Save/Export), keyboard-accessible.
   Clicking it auto-switches the recording tab to **Loop**. When the looper
   already holds a loop, the button uses the existing two-step arm pattern
   ("Replace loop?" → confirm); with an empty looper it loads immediately.
2. **Loaded-source indicator:** the transport snapshot ships
   `looperSourceName`; the looper shows a small "Loaded: `<name>`" chip while
   non-empty. It clears automatically on **Discard** or a **fresh capture** — no
   separate detach control.
3. **Channel mapping:** mono snippet into a multi-channel session duplicates to
   all channels; a wider snippet downmixes by averaging into the session's
   channels; equal widths copy 1:1. `recordBuffer` is cleared first.
4. **Capacity cap:** a snippet whose **resampled** length exceeds
   `maxRecordSamples / 2` (~60 s at the session rate) is rejected with an error
   notification; the half-buffer cap guarantees room for an overdub layer.
5. **Grid/BPM:** load the exact length and never call the capture grid-trim;
   session BPM is left untouched. A non-grid length is tolerated (the crop UI
   rounds); tempo detection remains ticket 0051's job.
6. **Resampler:** a new pure, CTest-covered `Source/Resampler.h/.cpp` wraps
   `juce::LagrangeInterpolator`; equal rates are a no-op copy. Message-thread
   only.
7. **Undo/guards:** loading is not undoable; it clears the 0030 layer
   undo/redo history and **Discard** is the escape hatch. It is refused while
   any capture is active (take or loop, count-in included) or a record is
   requested, and it first stops loop playback, snippet playback, take-review
   playback and melody audition.

**Current behavior:**
`SnippetLibrary` holds snippets as shared audio buffers (any channel count,
each with its own `sampleRate`). The looper is seeded only by a fresh capture
or an overdub layer; `saveLoopSnippet()` always writes a new timestamp-named
snippet from the current loop. `recordBuffer` is
`getTotalNumInputChannels()` × `maxRecordingSeconds` at the session rate.

**Desired behavior:**

1. Add a backend `loadSnippetIntoLooper(int id, juce::String& outError)`
   (message thread only):
   - Resolve the snippet; error if missing or empty.
   - Resample the snippet audio to the session rate via the pure `Resampler`
     module (no-op when the rates match).
   - Channel-map the result onto `recordBuffer`'s channel count (decision 3),
     after clearing `recordBuffer`.
   - Capacity-check the resampled length against `maxRecordSamples / 2` and set
     `outError` when it does not fit (decision 4).
   - Publish the loop descriptor through `Looper` (new `Looper::setLoaded`
     entry point: `start = 0`, `length = fullLength = resampled length`, crop
     cleared, position 0, `playing = false`, layer history cleared), refresh the
     waveform peaks from the loaded region, and reset the loop clip latch.
   - Record `looperSourceName` / `looperSourceId`; clear them on a fresh
     capture (`Looper::armFresh` path) and on `clearLoop()`.
   - Refuse while a take/loop capture or count-in is active, and stop loop,
     snippet, take-review and melody playback first.
2. Add `Source/Resampler.h/.cpp` — pure helpers
   `resample(buffer, srcRate, dstRate)` and
   `mapChannels(buffer, targetChannels)` returning a new buffer (identity at
   equal rates / equal widths), unit-tested in `Tests/test_Resampler.cpp`
   (length ratio, sine pitch preservation, mono→stereo duplication,
   stereo→mono average).
3. Register a new bridge event `frontendLoadSnippetIntoLooper { id }` in
   `WebViewEditor.h` / `.cpp` and mirror it in `bridge.js`; surface failures
   with the existing `sendNotification(..., "error")` toast and successes with
   an `"ok"` toast.
4. `saveLoopSnippet()` uses `<source name> overdub` as the default name when a
   source snippet is recorded, falling back to the existing timestamped
   `"Loop <…>"` for a freshly captured loop. `library.addSnippet` stays the
   single creation path; the source snippet and its files are never modified.
5. Ship `looperSourceName` in `backendTransport`; `SnippetCard` gets a
   `loopHasLoop` prop (from the transport) to drive the two-step replace
   confirm and emits the new event; `App.jsx` switches `recordingMode` to
   `"loop"` on load; `Looper.jsx` renders the loaded-source chip.

**Key interfaces:**

- `Source/Resampler.h/.cpp` (new pure module) + `Tests/test_Resampler.cpp`.
- `PluginProcessor::loadSnippetIntoLooper(int, juce::String&)`; `looperSourceName`
  / `looperSourceId` members; `saveLoopSnippet()` naming; `backendTransport`
  snapshot field.
- `Looper::setLoaded(int64_t)` (or equivalent) clearing history and publishing
  the descriptor.
- New bridge event `frontendLoadSnippetIntoLooper { id }` in `WebViewEditor.h`
  constants + handler and `bridge.js` (parity test must pass).
- `WebUI/src/components/SnippetCard.jsx` (button + confirm),
  `WebUI/src/components/SnippetList.jsx` (pass `loopHasLoop`),
  `WebUI/src/App.jsx` (wire event + tab switch),
  `WebUI/src/components/Looper.jsx` (source chip), `WebUI/src/styles.css`.

**Acceptance criteria:**

- [x] Loading a library snippet seeds the looper; the loop then plays, crops,
      zooms, reverses, half-speeds and overdubs exactly like a captured loop.
- [x] A snippet at a different sample rate is resampled to the session rate
      with no pitch/tempo shift; `Resampler` is pure and unit-tested.
- [x] Channel-count mismatches follow decision 3; `recordBuffer` is cleared so
      no stale audio leaks into the loaded loop.
- [x] A snippet whose resampled length exceeds `maxRecordSamples / 2` is
      refused with a clear error toast and the existing loop is left intact.
- [x] The loaded snippet is never modified in memory or on disk.
- [x] Overdubbing then saving creates a **new** snippet named
      `<source> overdub`; the source remains in the library unchanged.
- [x] Loading clears the layer undo/redo history, is refused during a capture,
      and stops loop/snippet/take-review/melody playback first.
- [x] The looper shows a "Loaded: `<name>`" chip that clears on Discard or a
      fresh capture; the UI switches to the Loop tab on load.
- [x] No new allocation or lock in `processBlock`; bridge parity and the CTest
      suite stay green.

**Out of scope:**

- Tempo-locked / time-stretched playback (0052) and backing-track import with
  tempo/key detection (0051) — this ticket loads audio at its own length and
  does not estimate a tempo from it.
- Automatic stem separation or splitting a snippet into parts.
- Non-destructive in-place editing of the loaded snippet (it is copied into the
  loop; the library entry is untouched).
- Undoing a load (only the layer history exists); drag-and-drop loading.
- Cloud/streaming sources or any change to snippet file formats.
