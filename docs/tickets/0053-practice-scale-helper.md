# Practice helper: scale/chord overlay from the detected key

## Problem

`KeyDetector` already estimates a snippet's key, and the tuner tracks the live
note, but neither is turned into a practice aid (which scale tones fit, where to
find them).

## Current behaviour

- `KeyDetector::detectKey` returns key, confidence and detected pitch classes
  for a snippet; the tuner publishes the live frequency/note.
- The library shows detected keys; there is no scale/chord or fretboard view.

## Open questions (resolve before implementation)

*Resolved during triage — see decisions 1–8 in the Agent Brief below.*

1. Input: the selected snippet's detected key, the live input (tuner ring), or a
   manually chosen key?
2. Presentation: guitar fretboard diagram, note-name strip, or scale-degree
   readout? Which tuning(s)?
3. Chords too (diatonic triads/sevenths) or scales only for v1?
4. Where it lives: extend the Tuner popover, its own header popover, or the
   snippet card?
5. Does it need `KeyDetector` to accept live audio rather than a stored buffer?

## Required change (proposed, pending answers)

- A pure scale/chord theory module (unit-tested) mapping key → scale/chord tones.
- A presentational component (fretboard/notes) fed by the detected key and/or the
  live note.

## Acceptance criteria

Resolved during triage — see the Agent Brief below for the concrete criteria.

## Docs

`CONTEXT.md` (new term), `webui-bridge` skill.

## Files

WebUI-first (`WebUI/src/components/…`, `WebUI/src/utils.js`); possibly
`Source/KeyDetector.*` for live input and a bridge event for the session key.

## Out of scope

Full tab/notation; audio-to-MIDI transcription.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Add a header practice popover that shows a scale on a guitar fretboard,
driven by a manual key, the playing snippet's detected key and the live tuner note.

**Decisions settled during triage:**

1. A **manual key selector**, prefilled from the **currently playing snippet's detected
   key** when one exists (otherwise the last chosen key), with the **live tuner note
   highlighted** on the display.
2. The theory lives in **JS (`WebUI/src/utils.js`)** — no C++ module, no bridge. (The
   repo has no JS test harness; this is a presentational, WebUI-first feature.)
3. Presentation: a **guitar fretboard diagram** (standard tuning, low-E to high-E).
4. Scales: **major, natural minor, major pentatonic, minor pentatonic, blues**.
5. **Scales only** in v1 — no chords.
6. It lives in its own **header "Scales" popover** (the header tools area, beside the
   Tuner).
7. **Share the pitch analysis**: opening the Scales popover also starts the tuner's live
   analysis (reusing the existing tuner-open event), so the live note highlights there.
   It must **not** change the tuner's monitor mute. Closing stops the analysis (the two
   tools popovers are mutually exclusive, so the open flag stays unambiguous).
8. The chosen **key + scale persist in `localStorage`** (frontend-only), like the
   recording-tab choice.

**Current behavior:**
`KeyDetector::detectKey` estimates a snippet's key (shipped per snippet, shown in the
library); the tuner publishes the live note (`tunerNote`/`tunerCents`) in the transport
snapshot only while its analysis is running. There is no scale/chord or fretboard UI and
no theory code.

**Desired behavior:**

1. Add pure JS theory helpers in `utils.js`: given a root and a scale id, produce the
   note set (and scale degrees) using the conventional accidentals for that key (sharps
   for sharp keys, flats for flat keys). Scale ids: major, natural minor, major
   pentatonic, minor pentatonic, blues.
2. Add a **Scales** popover component in the header tools. It has a root selector (12
   notes), a scale selector, and a fretboard diagram (standard tuning) that marks every
   in-scale note, highlights the root, and (when the pitch analysis is running)
   highlights the string/fret matching the live note. Out-of-scale notes are hidden or
   dimmed.
3. Key prefill: use the **currently playing snippet's detected key** when one is playing
   and detected; otherwise fall back to the persisted last-chosen key; **C major** when
   nothing is known. The user can always override manually.
4. Opening the popover emits the existing tuner-open event (starting the analysis) but
   never the tuner monitor-mute; closing emits the close. The tuner popover and the
   Scales popover are mutually exclusive (opening one closes the other).
5. The chosen root + scale persist in `localStorage` and are restored on load.
6. The popover is keyboard-operable and labelled (0017): focus on open, Escape closes,
   selectors and the fretboard carry accessible names; no new bridge event is added, so
   event parity is unchanged.

**Key interfaces:**

- `WebUI/src/utils.js` — pure scale helpers (root + scale id → notes/degrees, accidental
  spelling).
- A new header-tools popover component (e.g. `PracticeScales.jsx`) rendering the
  selectors + fretboard; `App.jsx` wires the playing-snippet key, the live tuner note
  and the tuner-open emit; `styles.css` for the popover/fretboard.
- Reuses the existing `frontendSetTunerOpen` event and the transport snapshot's
  `tunerNote`/`tunerCents`; no C++ or bridge changes.

**Acceptance criteria:**

- [ ] A header **Scales** popover with root + scale selectors and a standard-tuning
      fretboard; opens from the header tools, closes on Escape/outside.
- [ ] The fretboard marks the scale tones, highlights the root, and highlights the live
      note when the analysis is running.
- [ ] Opening the popover starts the pitch analysis (via the existing tuner-open event)
      without changing the tuner monitor mute; closing stops it; the two tool popovers
      are mutually exclusive.
- [ ] The key prefills from the playing snippet's detected key when available, else the
      persisted last choice, else C major.
- [ ] The chosen root + scale persist in `localStorage` across restarts.
- [ ] Accidental spelling follows the key (sharps vs flats).
- [ ] Theory helpers are pure JS in `utils.js`; the fretboard is a component.
- [ ] Keyboard-operable and labelled; **no new bridge event** (parity test unchanged);
      the WebUI build stays green.
- [ ] The five scales (major, natural minor, major/minor pentatonic, blues) render
      correctly for all 12 roots.

**Out of scope:**

- Chords (diatonic triads/sevenths).
- Alternate tunings, left-handed mode, capo, or 7/8-string layouts.
- A C++ theory module / CTest coverage (JS-only by decision 2).
- Tab/notation, audio-to-MIDI transcription, or scale practice exercises.

**Docs:** the `webui-bridge` skill (new component + popover pattern); `AGENTS.md` header
tools note if useful.
