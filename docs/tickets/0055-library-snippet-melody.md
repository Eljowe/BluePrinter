# Library snippet melody: analyse existing snippets and draw the piano-roll in the card

## Problem

0054 extracted a take's melody and persisted it with the saved snippet, but the
library could only show a note count (`melodyCount`) — the notes themselves were
never shipped to the frontend, and analysis was hard-wired to the selected take.
So a melody in the library could not be seen, and an existing (imported or
older) snippet could never be analysed at all.

## Current behaviour

- `snippetToVar` ships `melodyCount` only; `Snippet::melody` is never sent to React.
- `analyzeTakeMelody` reads `TakeRecorder::getSelectedTakeAudio()`; there is no
  path to `MelodyAnalyzer` for a library snippet.
- Audition (`MelodyPlayer`) is owned by the take review and keyed to the selected
  take, so the library has no way to play a snippet's melody.
- Saving a take already writes `melody` into the sidecar (`writeMetadataFile`) and
  `loadFromFolder` reads it back — that part worked; it was just invisible.

## Decisions

1. **Separate action.** The card's existing **Analyse** stays key + pitch classes
   (`KeyDetector`); a dedicated **Analyse melody** button runs the slower YIN pass,
   so key detection stays fast and melody extraction is on demand.
2. **Display + audition.** The expanded card draws the same `PianoRoll` the take
   review uses and reuses `MelodyPlayer` for a monitor-only **Play melody** toggle.
3. **Persist per snippet.** The result is written into the existing sidecar
   (`library.updateMelody` + `persistMetadata`), so a re-analysis survives reload.
   The analyser's key is only copied in when the snippet has no detected key.

## Agent Brief

> *This was generated by AI during implementation.*

**Summary:** Ship a snippet's melody notes to the frontend, add a per-snippet
melody analysis path, and surface a piano-roll + synth audition in the snippet card.

**Required change:**

1. `PluginProcessor::analyzeSnippetMelody(id)` mirrors `detectSnippetKeyAndNotes`:
   strong-ref the snippet audio, mark the id in-flight (a per-id generation
   counter lets a newer request supersede an older worker), run
   `MelodyAnalyzer::analyze` off the message thread, then `updateMelody` +
   `persistMetadata` and fire `libraryChanged`.
2. `setSnippetMelodyPlayback(id, enabled, startSample)` reuses `MelodyPlayer`,
   stopping snippet/take/looper playback first. The processor tracks which melody
   is sounding (`MelodySource { none, take, snippet }` + source id) so the take
   review and the cards can each show the right play/stop state.
3. `snippetToVar` ships the `melody` note array and a `melodyAnalysing` flag;
   `makeSnippetsSnapshot` sets the flag from `isSnippetMelodyAnalysing`.
4. The transport snapshot ships `melodyPlayingSource` + `melodyPlayingId`.
5. `SnippetCard` gets a **Melody** section: `PianoRoll`, key label, status,
   **Analyse melody** / **Re-analyse melody** and **Play melody** / **Stop melody**.

**Key interfaces:**

- Events `frontendAnalyzeSnippetMelody { id }` and
  `frontendSetSnippetMelodyPlayback { id, enabled, startSample? }` in
  `WebViewEditor.h` + `bridge.js`.
- `SnippetLibrary::updateMelody` (already existed) is now used by the analysis path.
- Tests: `SnippetSidecar_roundTripsMetadataThroughDisk` now asserts the melody
  array, and `SnippetLibrary_updateMelodyPersistsToSidecar` covers the
  `updateMelody` + `persistMetadata` reload path.

## Acceptance criteria

- [x] Analysing a library snippet runs off the message thread; a second request
      supersedes an in-flight one.
- [x] The result is persisted to the sidecar and survives a library reload.
- [x] The card draws the notes, shows the key, and can audition them (monitor
      only; refused during a capture).
- [x] The take review and the card each show the correct play/stop state.
- [x] Bridge parity passes; the CTest suite is green (164/164).

## Out of scope

- Polyphonic transcription, note editing, `.mid` export (0026 stays `wontfix`).
- Melody analysis of loop captures while they are still only in the looper
  (save the loop to the library first).
- Tempo-aware quantisation of the extracted notes.
