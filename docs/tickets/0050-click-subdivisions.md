# Click subdivisions and accents

## Problem

The click only marks beats, with beat 1 accented. Players practising slow
material or odd meters want eighth/sixteenth subdivisions and configurable
accents.

## Current behaviour

- `MetronomePlayer::setContext` takes sample rate, BPM, beats-per-bar (numerator)
  and `beatUnit` (denominator); it schedules a soft tick per beat and an accent
  on beat 1 (`ClickSynth`).
- There is no subdivision or per-beat accent pattern.

## Open questions (resolve before implementation)

*Resolved during triage — see decisions 1–7 in the Agent Brief below.*

1. Subdivision options: off / eighth / sixteenth / triplet? Fixed per meter or
   free choice?
2. Accents: just "accent beat 1" (today), a fixed alternating pattern, or a
   user-editable per-beat pattern (step UI)?
3. Distinct sounds: reuse the tick/accent voices at different gains, or add a
   third "sub" voice to `ClickSynth`?
4. Interaction with count-in, `clickDuringCapture`, and the free-running MIDI
   clock.

## Required change (proposed, pending answers)

- Extend `MetronomePlayer` scheduling to emit sub-clicks at the chosen division
  with a lower-gain voice.
- Persist the subdivision (and accent pattern if any) in the properties file
  like the other metronome settings.
- UI in the **Click sound** popover (`SyncControls.jsx`) or a small sync-strip
  cluster.

Resolved during triage — see the Agent Brief below for the concrete criteria.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Add per-beat subdivision clicks (off/eighth/triplet/sixteenth) and a
user-editable per-beat accent pattern to the metronome.

**Decisions settled during triage:**

1. Subdivision options: **off / 2 / 3 / 4** (eighth, triplet, sixteenth) per beat,
   chosen independently of the meter; **default off**; persisted like the other click
   settings.
2. Accents: a **per-beat on/off pattern** (length = the meter's beat count), default
   **beat 1 only**; unaccented beats use the normal tick, accented beats the accent
   voice; **sub-clicks are never accented**.
3. The accent pattern is stored as a **bool pattern resized on meter change** — keep
   the entries that fit, pad new beats off.
4. Placement: a small **subdivision selector beside Meter** in the sync strip; the
   **accent step row in the existing Click sound popover**.
5. Sub-clicks are produced by a **third derived `ClickSynth` voice** (tick pitch,
   fixed lower amplitude), pre-rendered like the existing tick/accent buffers; no new
   UI tunables.
6. Subdivisions and accents apply **everywhere the click plays** (count-ins, takes,
   loop captures, the free-running clock), under the existing master Click and
   Click: capture gates. The MIDI clock output stays **24 ppqn, unsubdivided**.
7. The feature is **render-only**: the beat clock, loop grid, fixed-length capture and
   count-in length are unchanged.

**Current behavior:**
`MetronomePlayer::render` schedules only whole beats (`beat * samplesPerBeat`) and
accents when `beat % beatsPerBar == 0`. `ClickSynth` renders two pre-made buffers
(tick + bar accent); the processor resynthesises them from the persisted click
params. There is no subdivision and no configurable accent pattern.

**Desired behavior:**

1. The metronome context gains a subdivision count (0/2/3/4) and an accent mask. On
   each block, for every beat it schedules, it renders the beat click from the tick or
   accent buffer according to the mask, then renders a sub-click at each of the
   `subdivision - 1` intermediate offsets (`beatSample + k * samplesPerBeat / subdivision`)
   using the sub buffer. Subdivision 0 reproduces today's output exactly.
2. The accent mask selects, per beat index modulo the pattern length (the meter's beat
   count), whether that beat uses the accent buffer. The default mask accents beat 1.
   Missing/empty buffers fall back to the tick as today. The pattern can be all-off.
3. `ClickSynth` gains a third voice rendered into its own buffer: same synthesis, a
   lower amplitude than the tick (its own fixed value), still deterministic and
   unit-tested. The player's `render` gains a sub buffer parameter alongside tick and
   accent; the processor pre-renders and hands it over on the message thread exactly
   like the other two.
4. State: the subdivision (int) and the accent mask are standalone user state, not
   APVTS parameters, shipped in the transport snapshot so the UI reflects a restore.
   The accent pattern crosses the bridge as an array of booleans and is stored
   internally as a per-beat mask (the supported meters cap at 12 beats, so a 16-bit
   mask suffices). Subdivision and mask persist in the properties file and round-trip
   through host state.
5. Meter change: when the time signature changes, resize the stored mask to the new
   beat count — keep the leading entries that fit, pad the new beats off; default to
   beat-1-only when there is no usable pattern. This happens on the message thread.
6. UI: the sync strip shows a subdivision selector beside Meter (Off / 8ths /
   Triplets / 16ths). The Click sound popover shows a bar-accent step row (one toggle
   per beat of the current meter) plus a reset-to-beat-1 affordance. Both are
   keyboard-operable and labelled; changes take effect on the next audio block.
7. MIDI clock output (`MidiClockMath`, 24 ppqn) is untouched; subdivisions are audible
   only.

**Key interfaces:**

- `MetronomePlayer` — context carries the subdivision + accent mask; `render` takes a
  third (sub) click buffer; scheduling emits the intermediate sub-clicks. Audio-thread
  only, no allocation on the common path (reserve room for more overlapping clicks).
- `ClickSynth` — a third derived voice/buffer following the existing pure, direct-test
  pattern.
- The processor — owns the subdivision atomic and the accent mask (message-thread-set,
  audio-thread-read), resynthesises the sub buffer with the other clicks, resizes the
  mask on `setTimeSignature`, ships both in the transport snapshot, and persists both.
- New frontend events (e.g. `frontendSetClickSubdivision { subdivision }` and
  `frontendSetClickAccents { accents: [...] }`) registered in both the editor's event
  constants and the JS `FRONTEND_EVENTS` map; parity is machine-checked. The snapshot
  gains the subdivision value and the accents array.
- The sync strip and the Click sound popover.

**Acceptance criteria:**

- [ ] Scheduling unit tests: subdivision 0 matches today's output; subdivisions 2/3/4
      place the extra clicks at the correct samples in each beat; sub-clicks are never
      accented; the accent mask selects which beats use the accent buffer; the default
      mask accents beat 1 only.
- [ ] `ClickSynth` unit tests cover the third sub voice (deterministic, softer than the
      tick).
- [ ] A meter change resizes the mask (keep what fits, pad off) and the default is
      beat-1-only when unusable.
- [ ] Subdivision and accent mask round-trip through the properties file and host
      state, with defaults 0 and beat-1-only.
- [ ] The transport snapshot ships the subdivision and the accent array; the UI
      reflects a restored state.
- [ ] Count-ins, takes, loop captures and the free-running clock all honour the
      subdivision/accent settings; the master Click and Click: capture gates still
      apply.
- [ ] The MIDI clock output remains 24 ppqn and is unchanged by subdivisions.
- [ ] The beat clock, loop grid, fixed-length capture and count-in length are
      unaffected.
- [ ] The bridge event parity test, the CTest suite and the WebUI build stay green.
- [ ] Manual smoke test on Windows: a 7/8 accent pattern plus eighth/sixteenth/triplet
      subdivisions are audible in a count-in and a capture.

**Out of scope:**

- Different time signatures (done, 0032); a full drum machine.
- Per-subdivision accents, swing/shuffle, or groove templates.
- Any change to the MIDI clock's ppqn or phase.
- Changing the count-in length or the beat clock.
- Per-meter saved accent patterns (decision 3: one mask, resized).

**Docs:** `AGENTS.md` (metronome / MIDI clock, click params) and the `juce-audio`
skill; add the new terms to `CONTEXT.md` if useful.
